# Countries from the Browser's Time Zone Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The dashboard shows a Countries panel (flag and name), with the country derived from the browser's time zone, never from the IP.

**Tech Stack:** let-go 1.13.0 with lgx 0.4.2, DuckDB through ragtime migrations, the tracker `resources/public/p.js`, React 19 / TypeScript in `ui/`, Playwright in `e2e/`, tz data (`zone.tab`, `tzdata.zi`) as the source of a checked-in table.

**Repo:** `~/Projects/pagelet`. Work on a branch `countries-from-time-zone` off `master`, and open a PR as the earlier work did. Run every command through mise (`mise exec -- lgx ...`).

---

## Design

### Approach

The tracker sends the browser's IANA time zone with every event. The server looks the zone up in a checked-in table of zone to two-letter country code, and stores both on the event row. A new ranked report counts visitors and pageviews by country, and the dashboard shows it with a flag emoji and the country's name.

Nothing about the IP changes: it is still read, hashed into the visitor id and dropped. There is no IP database, no new Go dependency and no file to ship beside the binary.

### Data flow

1. `p.js` reads `Intl.DateTimeFormat().resolvedOptions().timeZone` once at load and sends it as `z` in every payload (`{d, u, n, r, z, ...}`). When `Intl` is missing or the read throws, `z` is left out.
2. `parse-event` (`src/pagelet/ingest.lg`) looks `z` up in `pagelet.timezones/zone->country`. A hit puts `:timezone z` and `:country "NL"` on the row. Anything else (absent, not a string, not in the table) puts nil for **both**, so a client can never write an arbitrary string into either column.
3. The flusher's `insert-batch!` writes the two new columns.
4. `stats.lg` adds `:countries`, a `(ranked "country")` list like browsers: rows `{:name "NL" :visitors n :pageviews n}`, nulls skipped, top ten.
5. The dashboard turns `"NL"` into `🇳🇱 Netherlands` in the browser and renders it with the existing `RankedList`.

### The zone table

`src/pagelet/timezones.lg` is generated and checked in. It holds one def, a map from zone name to country code:

```clojure
(ns pagelet.timezones)
;; header comment: generated by scripts/gen-timezones.sh from tzdata <version>; do not edit
(def zone->country
  {"Africa/Abidjan" "CI"
   ...})
```

`scripts/gen-timezones.sh` builds it from the machine's tz data (`/usr/share/zoneinfo/zone.tab` and `/usr/share/zoneinfo/tzdata.zi`, version 2026c on the dev box) by these rules:

1. **Direct entries:** every non-comment row of `zone.tab` gives zone (column 3) to country (column 1). `zone.tab` has exactly one country per zone (418 rows), unlike `zone1970.tab`, which merges neighbours.
2. **Aliases:** every link line of `tzdata.zi` (`L <target> <name>`) whose name is **not** already a direct entry and whose target **is** one gives name to the target's country. This covers the legacy names browsers still report (`Asia/Calcutta`, `Europe/Kiev`, `Asia/Saigon`, `US/Pacific`).
3. **Excluded aliases:** the abbreviation-style names `CET`, `MET`, `EET`, `WET`, `EST`, `MST`, `HST`, `EST5EDT`, `CST6CDT`, `MST7MDT`, `PST8PDT`. Their link targets are arbitrary (`EST` links to `America/Panama`), so they would name a wrong country.
4. Links whose target is not in `zone.tab` (`UTC`, `GMT`, `Etc/*`) drop out by rule 2.
5. Output sorted by zone name, one entry per line, so a regeneration diffs cleanly.

On the dev box this gives 418 + 124 = 542 entries. The script takes the two input paths as optional arguments so it can run against another tz data copy, and prints the tz version (the `# version` line of `tzdata.zi`) into the file's header comment.

### Key decisions

- **Store the zone as well as the country.** Migration 005 adds nullable `timezone` and `country` varchar columns. The zone allows a region breakdown later and a re-map if the table improves. No zone panel is built now.
- **Mapping on the server, not in the tracker.** The tracker stays small and the table can change without sites reloading a script.
- **`z` on every event, not only page views.** Custom events get a country too; the cost is about 25 bytes per event.
- **Country codes leave the server as codes.** Names and flags are a display matter: `Intl.DisplayNames` gives the name and two regional-indicator characters give the flag. The UI needs no country table.
- **`RankedList` is untouched.** `Site.tsx` builds the label string for the Countries panel.
- **The tracker size claim changes.** `p.js` is 2045 bytes today and the README says "under 2 KB" twice; the new field takes it just over. The README will say "about 2 KB". Comments in `p.js` are not cut to keep the old wording.
- **Old rows have no country.** No backfill is possible; the panel shows only events recorded after the deploy.

### Accepted limits

- Browsers that report `UTC` (Tor, Firefox with fingerprinting resistance, machines set to UTC) get no country and are not a row in the panel.
- A visitor whose zone is set to a neighbouring country's is counted there.
- The zone is client-sent, like the URL and referrer, so it can be spoofed.
- Chrome and Edge on Windows have no flag glyphs and show the two letters instead; the name beside them still reads.

### Testing

- `test/pagelet/ingest_test.lg`: `parse-event` with a known zone, a legacy alias, `UTC`, a junk string, a non-string and no `z`; the flushed row carries both columns.
- `test/pagelet/stats_test.lg`: `:countries` ranks by visitors and skips nulls.
- `test/pagelet/db_test.lg`: five migrations, up and down.
- `e2e/tests/tracker.spec.js`: a browser context in `Europe/Amsterdam` produces `countries: [{name: "NL", ...}]` through the real tracker.
- `e2e/tests/dashboard.spec.js`: the Countries panel shows `Netherlands` for a posted event with `z`.
