# Public Sites Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A site can be marked public in its Settings; a public site's dashboard is readable by anyone with its link, without signing in, and nothing else is.

**Tech Stack:** let-go 1.13.0 with lgx 0.4.2, DuckDB through ragtime migrations, ruuter routes in `src/pagelet/routes.lg`, React 19 / react-router 7 / TypeScript in `ui/`, Playwright in `e2e/`.

**Repo:** `~/Projects/pagelet`. Work on a branch `public-sites` off `master` and open a PR, as the earlier work did. Run every command through mise (`mise exec -- lgx ...`).

## Design

### Approach

`sites` gets a boolean, off by default. The three read endpoints of one site (the site itself, its stats, who is online) answer an anonymous request when that site is public. Everything else keeps requiring the session: the site list, creating, editing, deleting. The public page is the dashboard's own `/sites/:id` page in a read-only mode, so there is one URL per site and no second set of screens.

### Data

Migration `006-add-sites-public`:

```sql
alter table sites add column is_public boolean default false   -- up
alter table sites drop column is_public                         -- down
```

No `not null`: DuckDB refuses constraints in `add column`. Existing rows take the default, and every insert writes the column explicitly. The column is `is_public` because `public` is a schema name in SQL; the JSON key is `public` (`is_public as "public"` in `site-columns` and in `db/sites`).

`db/create-site!` currently inserts positionally (`insert into sites values (?, ?, ?, now()...)`), which breaks once the table has five columns. It must name its columns.

### API

A site's JSON gains `"public": true|false` everywhere a site is returned.

| Route | Signed in | Anonymous |
|---|---|---|
| `GET /api/sites/:id` (new) | the site, or 404 | the site if public, else 401 |
| `GET /api/sites/:id/stats` | as today | as signed in if public, else 401 |
| `GET /api/sites/:id/realtime` | as today | as signed in if public, else 401 |
| `PUT /api/sites/:id` | body may carry `public` | 401, as today |
| everything else | unchanged | unchanged |

- An anonymous request gets the **same 401** for a private site and for an id that names no site, so the API does not say which ids exist. Only a signed-in request sees 404.
- `PUT` body: `{"domain": "...", "name"?: "...", "public"?: true|false}`. `public` absent leaves the flag as it is; present and not a boolean is 400 (`"public must be true or false"`). `domain` stays required, so the dashboard's toggle sends the current domain along.
- `POST /api/sites` ignores `public`; a new site is private.
- In `routes.lg` this is one new wrapper beside `protected` and `with-site`:

  ```clojure
  ;; (handle req site) when the caller may read the site in the path:
  ;; signed in (404 for no such site), or anyone when the site is public.
  readable (fn [handle]
             (fn [req]
               (let [site (db/site-by-id db (-> req :params :id))]
                 (cond
                   (signed-in? req) (if site (handle req site) not-found)
                   (:public site)   (handle req site)
                   :else            unauthorized))))
  ```

  The file's header comment ("Public: health, the tracker, login, static files") gains the public sites' read routes.
- The request path still runs no SQL of its own: `db.lg` owns the changed queries.

### Dashboard

- `ui/src/api.ts`: `Site` gains `public: boolean`; `api.site(id)` for `GET /api/sites/:id`; `api.updateSite(id, domain, isPublic?)` sends `public` only when given.
- `App.tsx`: `/sites/:id` moves out of `Guarded` into its own route that waits for the session check (`state === 'checking'` renders nothing) and then renders the same `<main>` column and `SitePage` for both states. `/` and `/sites/new` stay guarded.
- `Site.tsx` reads `useSession()`:
  - **signed in**: as today (`api.sites()` feeds the switcher).
  - **signed out** (viewer): loads `api.site(id)` instead of the list. Its own 401 (private or unknown site) comes back as the value `'denied'`, never as an error, and only that renders `<Navigate to="/login" replace />`, which is what an anonymous visitor to `/sites/:id` gets today. `useSignedOutOn` stays, so a session that expires while on a public site drops the page into viewer mode instead of to the login page.
- Viewer mode shows the same report (stat cards, chart, Right now, all breakdowns, period control with the period in the URL) and differs only in the chrome:
  - `TopBar` gets a `viewer` prop: the wordmark is not a link, the site is a plain label (`SiteMark` and domain, no switcher), there is no Settings and no sign-out; a "Sign in" link to `/login` takes their place.
  - A site with no events shows a plain card "No visits recorded yet." instead of `Waiting` (no tracking code, no polling).
- Settings dialog (`ActionsMenu.tsx`): a new section between Domain and Delete, "Public dashboard": a checkbox labelled "Anyone with the link can view this dashboard" that saves on change (`api.updateSite(site.id, site.domain, checked)`), stays in the dialog, and reloads the site list so the prop is fresh. While public, the section shows the link (`${location.origin}/sites/${site.id}`) in a read-only field with a Copy button, following the copy pattern in `Snippet.tsx`. A failed save shows an alert and leaves the box as it was.
- Overview (`Sites.tsx`): a public site's card carries a small "Public" badge beside its domain.

### Key decisions

- **A flag per site, not share links with tokens.** The request is "make some sites public". The link is the dashboard URL; the 12-hex site id in it is not a secret and is not treated as one. Turning the flag off closes the page at once.
- **Same URL and same page for owner and visitor**, with a viewer mode, rather than a separate `/share/...` route and page: nothing to keep in sync.
- **Realtime is public too** for a public site, as is every breakdown including custom events and their counts. A site with something to hide in its events should stay private; the Settings wording says the whole dashboard is shared.
- **Anonymous gets 401, never 404**, so ids cannot be probed.
- **No `noindex`, no rate limit, no caching** on the public endpoints. The queries cost the same as the owner's; a crawler would need the link. Revisit if a public site gets heavy traffic.
- **After signing in from a public page the user lands on `/`**, as every login does today; no return-to parameter.

### Testing

- `test/pagelet/db_test.lg`: six migrations; rollback of six.
- `test/pagelet/routes_test.lg`: a new `public-sites` test for the table above, and the `public` field in `sites-crud`.
